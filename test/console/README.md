# Node.js v25 `console` corpus

The bar for `node:console` is Node's own `test/parallel/test-console*.js` — 22
files at `v25.0.0`, listed in [`NODE_TESTS.txt`](NODE_TESTS.txt). The per-test
result, with the first line of each failing run's stderr, is in
[`RESULTS.md`](RESULTS.md), regenerated by

```sh
bash zun-node/tools/run_node_tests.sh --zun target/debug/zun --module console
```

`console` is a **`zun-ts`** module: it is argument validation,
`util.formatWithOptions`, and a `write` call on whatever the caller supplied, so
there is no native extension and no `--ext`. Each test is bundled by
`tools/bundle_node_test.sh` and run as `zun run <bundle.ts>`.

## The two things to know before reading the table

### 1. `console` is in every bundle, because it is a global

`src/console/console.ts` is the only module file besides `src/timers/timers.ts`
in `BUNDLE_FILES` rather than `CONDITIONAL_FILES`. Node's `console` is a global
that is also the value of `require('console')`, and the engine's prelude
`console` has five of its nineteen methods — a call to any of the other
fourteen is a *compile* error, not a missing method. A corpus that calls
`console.table`, `console.group` or `console.count` on the global therefore
needs the real module present whether it requires it or not.

### 2. The identifier `console` cannot carry a method call, so the bundler renames the receiver

Two engine behaviours compound here, and between them they make the name
unusable as a receiver:

- Eleven method names — `log`, `info`, `debug`, `warn`, `error`, `group`,
  `groupCollapsed`, `groupEnd`, `count`, `countReset`, `assert` — are
  intercepted by the checker (`zun_sema/src/check.rs`'
  `check_console_variadic`) and lowered to the prelude's own console **with no
  user-declaration guard**. The sibling computed-key path *does* guard on
  `cx.lookup(...)`, so `console[method](...)` honours a program's own binding
  while `console.method(...)` does not.
- A module-level `const console` is visible to `console.<method>` only at **top
  level**. Inside a function the same call resolves against the prelude
  namespace instead and dies at run time with
  `call did not resolve to a method` — related to
  [zun#34](https://github.com/UrubuCode/zun/issues/34), but for a plain `const`
  rather than a destructuring.

`src/console/global.ts` therefore binds the one console object under **two**
names, `console` and `__zunConsole`, and `tools/bundle_node_test.sh` rewrites
receiver positions (`console.` followed by an identifier, and `console[`) to the
second name. Every other use of the word is left alone, so
`const { Console } = console` and `globalThis.console` still read the name a
Node program expects, and a `console.log` that is *data* — inside
`execNode('-e "console.log(1)"')` or `eval('console.log("FOO");…')` — is not
touched, because the rule refuses a quote immediately before the name.

Repros for both halves:

```ts
class Con {
  log(...a: any[]): void { host.stdoutWrite("MY log\n"); }
  count(label?: any): void { host.stdoutWrite("MY count\n"); }
  dir(o?: any): void { host.stdoutWrite("MY dir\n"); }
}
const console: any = new Con();
console.log("a");      // prelude: prints "a",        not "MY log"
console.count();       // prelude: prints "default: 1", not "MY count"
console.dir({});       // this class: "MY dir"
function inside(): void { console.dir({}); }
inside();              // zun: runtime error: call did not resolve to a method
```

`node` runs all four against the program's own `console`.

## Repro for the new engine bug

`String.prototype.trimLeft` / `trimRight`, the Annex B aliases of `trimStart` /
`trimEnd`:

```ts
const s: any = "  hi  ";
s.trimStart();   // "hi  "
s.trimEnd();     // "  hi"
s.trimLeft();    // zun: runtime error: call did not resolve to a method
```

`node` prints `'hi  '`, `'  hi'`, `'hi  '`. The two legacy names are required by
Annex B of the specification and are what Node's own test file uses.

## What this module does cover

Everything in `lib/internal/console/constructor.js`, `lib/internal/cli_table.js`
and the `time`/`timeLog`/`timeEnd`/`formatTime` half of
`lib/internal/util/debuglog.js`:

- `new Console(stdout, stderr?, ignoreErrors?)` and the options form
  `{ stdout, stderr, ignoreErrors, colorMode, inspectOptions, groupIndentation }`,
  with Node's `ERR_CONSOLE_WRITABLE_STREAM`, `ERR_INVALID_ARG_TYPE`,
  `ERR_OUT_OF_RANGE` (`an integer` and `>= 0 && <= 1000`),
  `ERR_INVALID_ARG_VALUE` for `colorMode` and `ERR_INCOMPATIBLE_OPTION_PAIR` for
  `inspectOptions.colors` together with `colorMode`.
- `log`, `info`, `debug`, `dirxml`, `warn`, `error`, `dir`, `trace`, `assert`,
  `clear`, `count`, `countReset`, `group`, `groupCollapsed`, `groupEnd`, `time`,
  `timeEnd`, `timeLog`, `table`, and the inspector's no-op `profile`,
  `profileEnd`, `timeStamp`.
- Per-instance group indentation, including the multiline and object cases and a
  custom `groupIndentation`.
- `console.table`'s exact rendering: the box-drawing characters, the
  `(index)`/`(iteration index)`/`Key`/`Values` columns, `maxArrayLength: 3`, the
  `depth: -1` rule for an object with more than two keys, and a real
  `getStringWidth` so a full-width character takes two columns and a combining
  mark takes none.
- `formatTime`'s four shapes (`n.nnnms`, `s.ssss`, `m:ss.mmm`, `h:mm:ss.mmm`),
  exercised directly by `test-console-formatTime.js` through
  `require('internal/util/debuglog')`.
- The five `console.<level>` diagnostics channels, publishing the
  *unformatted* argument list so a subscriber can mutate it and see the change
  in the output — `test-console-diagnostics-channels.js` passes.
- `require('console')` is the global console object and carries
  `console.Console`, as in Node.

## Deviations this module documents rather than hides

- **`Console(out, err)` without `new`** returns an instance in Node
  (`ReflectConstruct(Console, arguments)`). There is no function-constructor
  model here (zun#25) and a class cannot be called, so only the `new` form
  exists.
- **No error callback on `stream.write`.** Node passes a write-error handler as
  the second argument and brackets the write with a temporary `'error'`
  listener. Here the bracket is applied only when the stream actually has
  `listenerCount`/`once`/`removeListener`, and the handler is dropped — a
  console stream need only answer `write(chunk)` until `node:stream` lands.
  `_ignoreErrors` still decides whether a throwing `write` propagates, and a
  stack overflow is still re-thrown rather than swallowed.
- **The write goes through the `write` *slot*, not the method.** Node's tests
  capture output by assigning `process.stdout.write = fn`. After that
  assignment the method call `stream.write(text)` no longer resolves in this
  engine — the original object-literal method sits in a side store that the data
  property shadows without replacing
  ([zun#32](https://github.com/UrubuCode/zun/issues/32)) — so
  `__consoleStreamWrite` reads the slot and calls the value, falling back to the
  method call for a stream whose `write` is a *class* method (which reads back
  `undefined`, zun#19). No receiver is threaded either way (zun#1).
- **`console.table` accumulates its columns in a `Map`.** Node uses
  `{ __proto__: null }`, which is the fix for CVE-2022-21824: a
  prototype-bearing accumulator let a user-supplied column name such as
  `__proto__` write through to `Object.prototype`. A null-prototype object is
  not a safe accumulator in this engine either — a computed read with a variable
  key still resolves `Object.prototype`'s members on one
  ([zun#46](https://github.com/UrubuCode/zun/issues/46)) and a `__proto__`
  assignment is unconditional ([zun#47](https://github.com/UrubuCode/zun/issues/47))
  — so the accumulator is a `Map`, which has no prototype to pollute, no
  inherited key to collide with, and the insertion order `ObjectKeys` gave Node.
  `console.table([{ foo: 10 }], ['__proto__'])` renders the empty `__proto__`
  column and leaves `'0' in Object.prototype` false.
- **`console.table` of a Map/Set *iterator* consumes it.** Node tells
  `map.entries()`, `map.keys()`, `map.values()` and `set.values()` apart by
  internal type and previews one without consuming it (`previewEntries`). This
  engine reports the class tag `[object Array Iterator]` for all four and has no
  preview, so the iterator is drained and the key/value case is recognised by
  what it yields (a run of two-element arrays). The four shapes Node's test uses
  come out right; a plain array iterator, which Node renders as an empty table,
  is rendered here as a values table, and the iterator is spent afterwards.
- **`ToString(Symbol)` is checked by hand.** `console.time`, `count` and
  `countReset` coerce their label with a template literal, which the
  specification requires to throw for a symbol. The engine's coercion answers
  `"Symbol(x)"` instead, so `__consoleLabel` raises the `TypeError` itself —
  which is what `test-console-count.js` asserts.
- **`console.time` measures with `Date.now()`**, in Node's
  `[seconds, nanoseconds]` shape, because `process.hrtime()` is still the
  placeholder `[0, 0]` in `src/process/process.ts`. The resolution is a
  millisecond, which is all `formatTime` prints; `console._times` is a real
  `Map` holding those pairs, as the corpus expects.
- **`console.trace`'s stack** comes from a fresh `Error`'s own `stack` rather
  than `ErrorCaptureStackTrace`. The first line is Node's
  (`Trace: <formatted>`); the frames below it are the engine's own format.
