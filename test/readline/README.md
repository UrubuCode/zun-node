# Node.js v25 `readline` corpus

The bar for `node:readline` and `node:readline/promises` is Node's own
`test/parallel/test-readline*.js` — 22 files at `v25.0.0`, listed in
[`NODE_TESTS.txt`](NODE_TESTS.txt). The per-test result, with the first line of
each failing run's stderr, is in [`RESULTS.md`](RESULTS.md), regenerated by

```sh
bash zun-node/tools/run_node_tests.sh \
  --zun target/release/zun \
  --ext zun-node/target/debug/zun_node.dll \
  --module readline
```

`readline` is a **`zun-ts+ext`** module, and the `+ext` is not about readline.
The module itself — `src/readline/readline.ts`, `src/readline/callback.ts`,
`src/readline/promises.ts` — is pure Zun TypeScript over `events`, `stream`,
`string_decoder` and `timers`; it imports no native. But three files in the
corpus read their input from a *file*
(`test-readline-async-iterators.js`, `test-readline-async-iterators-destroy.js`
and `test-readline-input-onerror.js` each build a `fs.createReadStream`), and
`fs` is syscalls, so the bundle is run as `zun run --ext <lib> <bundle.ts>`.

## The one thing to know before reading the table: two `Interface` classes

`node:readline` and `node:readline/promises` both export a class called
`Interface`, and they are different classes: the first takes a callback,
`rl.question(query, cb)`, the second returns a promise,
`await rl.question(query)`.

The name has to be a **top-level class** in the bundle, not a member of the
module object, because `new <object>.Ctor()` does not reach the constructor in
this engine ([zun#18](https://github.com/UrubuCode/zun/issues/18)) while Node's
own tests spell the constructor `new readline.Interface(...)` — so
`tools/bundle_node_test.sh` rewrites `readline.Interface` to the bare name. And
two top-level declarations of one name are a compile error in a single Zun
program.

So the module is three files: the shared base `__RlInterface` and everything
around it in `src/readline/readline.ts`, and one `class Interface extends
__RlInterface` in each of `src/readline/callback.ts` and
`src/readline/promises.ts`. No test in this corpus requires both modules, so the
bundler's `CONDITIONAL_FILES` inlines exactly one of the two.

| A **class declaration is program-global**, so the same name in two sibling blocks is `duplicate class` | `test-readline-tab-complete`, `test-readline-promises-tab-complete` | Both files declare `class FakeInput extends EventEmitter` once per `{ … }` block — three and two times respectively. The decoder it tests is otherwise exercised end to end by `test-readline.js` and `test-readline-emit-keypress-events.js`, which pass. |
| **ESM**: the bundler rewrites CommonJS `require`, and the engine has no `import` ([zun#4](https://github.com/UrubuCode/zun/issues/4)) | `test-readline-promises-csi` | The only `.mjs` file in the corpus. Its subject, the `Readline` class, is implemented in full (`cursorTo`, `moveCursor`, `clearLine`, `clearScreenDown`, `commit`, `rollback`, `autoCommit`). |
| `fs.createReadStream` is not implemented | `test-readline-async-iterators`, `test-readline-async-iterators-destroy` | Both read their lines out of a temporary file. The async iteration itself is verified against `Readable.from` and a `PassThrough`, and `test-readline-input-onerror.js` — which wants the *error* from a missing file — passes. |
| `Readable.prototype.resume` delivers synchronously instead of scheduling the flow | `test-readline-async-iterators-backpressure` | The test pushes three chunks into a `Readable({ read() {} })` and asserts the reader is observed un-paused once per chunk. The watermark bookkeeping matches Node exactly — four pauses, three resumes, 2050 queued after the first `next()`, `watermarkData.high` 1024 and `.size` tracking the queue — but Node's `resume()` flips `isPaused()` at once and delivers on the *next tick*, where this engine's delivers the next buffered chunk inside the call. So the queue is refilled and re-paused before the consumer's loop body runs, and `assert.strictEqual(notPaused, 3)` sees 1. Deferring the iterator's `resume()` call by a tick does not help: then `isPaused()` is still true when the body looks. The two halves have to be separable in `src/stream/stream.ts`. The tracker reports this one as a *timeout* rather than an assertion, because 6156 lines through the whole stack take longer than the 20 s budget in the Tier-0 interpreter; run it on its own with `--timeout 60` to see the assertion. |

## Repro for the new engine bug

A top-level `let` that a **function declaration** assigns to is not the same
binding the module scope and an arrow function read:

```ts
let keys: any[] = [];
const push: any = (k: any) => { keys.push(k); };
function reset(): void { keys = []; }
function check(label: string): void { host.stdoutWrite(label + JSON.stringify(keys) + "\n"); }

push("one");
check("after push one: ");   // ["one"]   — node ["one"]
reset();
check("after reset: ");      // []        — node []
push("two");
check("after push two: ");   // []        — node ["two"]
host.stdoutWrite(JSON.stringify(keys) + "\n");  // ["one","two"] — node ["two"]
```

`reset()` and `check()` operate on one slot; the module scope and the arrow
`push` operate on another. Node prints `["one"]`, `[]`, `["two"]`, `["two"]`.
Related to [zun#34](https://github.com/UrubuCode/zun/issues/34) (top-level
destructuring is invisible to functions) and
[zun#81](https://github.com/UrubuCode/zun/issues/81) (a top-level block's
bindings leak into module scope), but neither covers a plain `let` written
through a function declaration.

## What this module does cover

All of `lib/readline.js`, `lib/readline/promises.js`,
`lib/internal/readline/{utils,callbacks,emitKeypressEvents,interface,promises}.js`
and the memory half of `lib/internal/repl/history.js`:

- `createInterface` / `new Interface` in both the four-argument and the options
  form, with `input`, `output`, `completer`, `terminal`, `historySize`,
  `history`, `removeHistoryDuplicates`, `prompt`, `crlfDelay`,
  `escapeCodeTimeout`, `tabSize` and `signal`, and Node's validation for each
  (`ERR_INVALID_ARG_VALUE` for a non-function `completer` and a non-finite
  `escapeCodeTimeout`, `ERR_INVALID_ARG_TYPE` for a non-array `history`,
  `ERR_OUT_OF_RANGE` for a negative `historySize`).
- The events: `line`, `close`, `pause`, `resume`, `history`, and `SIGINT` /
  `SIGTSTP` / `SIGCONT`.
- `question` in both shapes — the callback one in `src/readline/callback.ts`,
  the promise one in `src/readline/promises.ts` — each with an `AbortSignal`,
  and `kQuestionCancel`'s restoration of the old prompt.
- `prompt([preserveCursor])`, `setPrompt`, `getPrompt`, `write(d[, key])`
  including every key sequence the line editor understands, `pause`, `resume`,
  `close`, and `ERR_USE_AFTER_CLOSE` from `question`/`write`/`pause`/`resume`
  after close.
- `line`, `cursor`, `getCursorPos()` and the display arithmetic behind them:
  `getStringWidth` with the full-width and zero-width code-point tables, tab
  alignment to `tabSize`, the wide-character wrap rule, multiline rows and the
  `| ` continuation prompt.
- `for await (const line of rl)`, with the queue, the high/low watermark pause
  and resume, and `Symbol.for('nodejs.watermarkData')`.
- The whole line editor: insert, `backspace`/`delete`, left/right by code point,
  `home`/`end`, word left/right and word delete in both directions, line delete
  left/right with the 32-entry kill ring, yank and yank-pop, the 2048-entry
  undo and redo stacks, history navigation with substring search, and multiline
  up/down movement.
- `emitKeypressEvents`, the escape-sequence state machine (xterm, gnome, rxvt,
  putty, Cygwin and bracketed-paste forms, modifiers, the escape-code timeout)
  and the `keypress` event shape.
- `clearLine`, `clearScreenDown`, `cursorTo` and `moveCursor` as module
  functions — with `NaN` rejection, `ERR_INVALID_CURSOR_POS`, the
  callback-validation rule and the null-stream no-op — and the `Readline` class
  of `readline/promises` with `autoCommit`, `commit` and `rollback`.
